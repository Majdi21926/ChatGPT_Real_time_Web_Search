# Migration Plan: Add Tavily as configurable search provider alongside DuckDuckGo

**Unit ID:** duckduckgo-to-tavily
**Search Provider:** DuckDuckGo (duckduckgo_search==8.0.1)
**Migration Strategy:** additive

## Objective

Introduce Tavily as an additive, configurable search backend that can be selected at runtime or used as a fallback when DuckDuckGo rate-limits. Keep all existing DuckDuckGo logic intact.

## Implementation Steps

1. Add tavily-python to requirements.txt
2. Add search_provider and tavily_api_key fields to configs/app_config.yml
3. Extend LoadConfig to read search_provider and TAVILY_API_KEY (env var override supported)
4. Implement TavilySearch class in src/utils/web_search.py covering retrieve_results and search_text using tavily.TavilyClient; keep all existing DDGS methods
5. Update Apputils.execute_json_function to check configured provider and dispatch to TavilySearch or WebSearch; add Tavily as automatic fallback when DuckDuckGo raises a rate-limit exception
6. Optionally expose a search provider selector in the Streamlit sidebar (src/app.py) for runtime switching

## Files to Modify

### `requirements.txt`
- Add tavily-python dependency alongside existing duckduckgo_search

### `configs/app_config.yml`
- Add a search_provider field (e.g. 'duckduckgo' | 'tavily') and a placeholder for TAVILY_API_KEY so it can be sourced from config or env

### `src/utils/load_config.py`
- Read the new search_provider field and TAVILY_API_KEY from config/env and expose them as attributes

### `src/utils/web_search.py`
- Add a TavilySearch class (or Tavily methods on WebSearch) implementing retrieve_results and search_text using the Tavily client; keep existing DDGS methods untouched

### `src/utils/app_utils.py`
- Update execute_json_function and wrap_functions to route calls to TavilySearch or WebSearch based on configured provider; use Tavily as fallback on DuckDuckGo rate-limit errors

## Dependency Changes

- Add tavily-python (latest)

## Environment Variable Changes

- Add TAVILY_API_KEY (new, required only when search_provider=tavily or as fallback)

## Notes

DuckDuckGo does not require an API key; Tavily does. The rate-limit retry logic already in WebSearch makes Tavily a natural fallback: catch the Ratelimit exception and re-try via TavilySearch.retrieve_results before sleeping. Tavily's /search endpoint covers text search well; image/video/map/news endpoints have no direct Tavily equivalent, so those methods should remain DuckDuckGo-only regardless of provider setting.
